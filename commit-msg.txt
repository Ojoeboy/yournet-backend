Fix print leak, add QR & payment auto-connect for voucher portal

- print.html: hide #yournetLangSwitcherContainer (profile icon +
  language dropdown) and #app-mobile-shell (bottom nav/drawer) when
  printing. Both were injected by shell.js/mobile-shell outside the
  existing print-hide list, so they leaked onto printed voucher
  sheets. Card grid layout (5x10 A4 sheet) untouched.

- vouchers.js / agents.js qrcode routes: encode
  {APP_BASE_URL}/p/{siteId}?code=XXXX-XXXX instead of the bare
  voucher code, so scanning opens the portal directly. Falls back to
  the plain code if APP_BASE_URL isn't set.

- portal.html: read ?code= from the URL, prefill the code input
  (through the same formatter used for manual typing), and
  auto-submit via the existing redeem() flow. Scanning now behaves
  as a genuine one-tap connect; redeem() still runs identically to
  manual entry, so expired/used/wrong-site codes fail the same way.

- portal.js gateway-callback route: apply the same auto-connect
  treatment to Paystack/Flutterwave purchase confirmations. On
  success, link to and auto-redirect (3s meta-refresh) to
  /p/{siteId}?code=..., so a card purchase no longer requires the
  customer to copy the code off a plain confirmation page and
  paste it in manually. Falls back to the old bare-code page when
  APP_BASE_URL isn't configured. Hubtel is unaffected — it confirms
  via server-to-server webhook + SMS and never routes through this
  page.
