fix(security): close billing double-charge race and add JWT revocation on password reset

- subscriptionBilling.js: runMonthlyBilling's FOR UPDATE SKIP LOCKED never
  actually held its lock (query ran without an explicit transaction, so
  Postgres autocommit released it the instant the SELECT returned). Split
  into a lock-free candidate lookup + chargeTenantById(), which now wraps
  SELECT FOR UPDATE SKIP LOCKED, the Paystack charge, and the status write
  in a single transaction on one held connection. Two overlapping billing
  passes can no longer both charge the same tenant.

- db/schema.sql: add tenants.token_version and tenant_users.token_version
  (default 0), idempotent ALTER TABLE ADD COLUMN IF NOT EXISTS.

- middleware/auth.js: requireAuth now checks the JWT's embedded `tv` claim
  against the live token_version in the DB and rejects stale tokens.
  Wrapped in a non-async entry point (requireAuthAsync().catch(next))
  since requireAuth is wired up directly via router.use(...) everywhere
  without asyncHandler, and Express 4 won't catch a rejected promise from
  async middleware on its own.

- routes/auth.js, routes/agents.js: embed tv (current token_version) in
  every tenant/agent JWT at issuance (signup, login, verify-secret
  re-issue). Bump token_version on tenant reset-password and agent
  reset-password, so a password reset actually invalidates any
  previously-issued token instead of leaving it valid until natural
  (up to 7-day) expiry.

Migration required before deploy: `npm run migrate`
