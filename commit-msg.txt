fix(license): record missing signup/reactivation revenue + add temporary mobile-nav diagnostics

Revenue recording fix:
- routes/auth.js (/signup): subscription_payments - the only table
  /admin/revenue-summary reads from - was never written to for a new
  signup. Root cause: a signup's payment is confirmed and the key issued
  (routes/license.js fulfillOrder) BEFORE any tenant exists, and
  subscription_payments.tenant_id is NOT NULL - there was no valid
  tenant_id to insert with until the tenant is actually created, which
  only happens later, at key redemption. Added the missing INSERT at that
  point instead - inside the same transaction as tenant creation, so the
  payment record and the tenant are created atomically together. Covers
  every payment method uniformly (Paystack/Flutterwave/Hubtel gateway
  checkout, and owner-approved manual MoMo claims) since issueKey()
  already stores amount/payment_method/payment_reference on the key
  itself regardless of how it was purchased.
- routes/auth.js (/reactivate): same gap for a reactivation redeemed via
  a manually-issued key - tenantId is known here but the insert was
  missing too. Fixed the same way. (Gateway-purchased reactivation, paid
  straight through checkout, already recorded correctly via
  fulfillOrder's 'reactivate' branch in routes/license.js - not touched.)
- Both inserts use ON CONFLICT (provider, provider_reference) WHERE
  provider_reference IS NOT NULL DO NOTHING, matching the existing
  partial unique index exactly - a plain ON CONFLICT (provider,
  provider_reference) would have thrown at runtime against a partial
  index and broken signup entirely; caught before shipping.
- kind='initial' on both, matching owner-revenue.html's existing
  "Signup / reactivation" vs "Monthly renewal" grouping - not a new
  label.

Note: this fix is forward-looking only. A payment that already completed
before this deploy needs a one-time manual SQL backfill (see chat) -
pulls tenant_id, amount, provider, and reference automatically from the
tenant's own already-issued license_keys row.

Diagnostics (temporary):
- public/license-admin.html: two on-page diagnostic scripts investigating
  a separate, still-unresolved issue - the mobile bottom nav not
  appearing on owner pages on a real device, reproducible even on a
  fresh browser and after deploying the earlier sw.js fix, which rules
  out stale-cache as the cause. Static review of the HTML/CSS/JS/routing
  found nothing wrong, so these render the actual runtime state directly
  on the page (viewport width, whether shell.js ran, #app-sidebar's
  content, .app-bottom-nav's real computed display, SW controller state)
  as visible banners - no remote debugging/adb required. Safe to remove
  once the cause is found; not tied to the revenue fix above.
