Add tenant wipe utility with production safety guard; skip idle site polling

- Add src/db/wipe-tenants.js: destructive one-time script to fully reset
  tenants/sites (and everything cascading from them - users, packages,
  vouchers, licenses, PPPoE data, etc.) via TRUNCATE ... CASCADE. Purges
  each tenant/site's R2 logo object first via storage.deleteLogo().
  Refuses to run without --yes; additionally requires typing back the
  exact DATABASE_URL hostname when it isn't localhost, so it can't be
  run against production/Neon by muscle memory alone.
- Add wipe:tenants script to package.json (npm run wipe:tenants -- --yes).
- Update src/server.js: pollAllSites() now returns early when the sites
  table is empty, skipping the per-site ping/UPDATE loop instead of
  running it against zero rows on every 5-minute cycle.

Reduces wasted Neon compute-hour usage during low/no-tenant periods
(testing, early onboarding) and gives a safe, repeatable way to reset the
database between test cycles without hand-writing SQL against production.
No changes to /health, R2 upload/delete behavior, or the logo migration
script.
