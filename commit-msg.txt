Move tenant/portal logos to Cloudflare R2 object storage

- Add src/services/storage.js: S3-compatible R2 client for uploading/
  deleting logo images, with automatic fallback to base64 data: URLs
  if R2 env vars aren't configured
- Update src/routes/dashboard.js: account logo upload now stores the
  R2 URL in tenants.account_logo instead of a base64 blob; deletes the
  replaced object from R2 on upload/delete
- Update src/routes/sites.js: portal logo upload follows the same
  pattern for sites.portal_logo_url
- Add src/db/migrate-logos-to-r2.js: one-time, idempotent script to
  backfill existing base64 rows in tenants/sites to R2 (npm run
  migrate:logos)
- Add @aws-sdk/client-s3 dependency and migrate:logos script to
  package.json
- Add R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY,
  R2_BUCKET_NAME, R2_PUBLIC_URL to .env.example

Reduces Postgres row size/storage pressure on Neon's free tier as
tenant count grows. No changes to /health or the site polling job.
