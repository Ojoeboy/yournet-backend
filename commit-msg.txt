Fix silent email-send failures: log actual SMTP result instead of swallowing errors

- sendEmail() in src/integrations/emailService.js now logs
  [EMAIL SENT] with messageId/response on success, and
  [EMAIL FAILED] with the real error message on failure, then
  rethrows so it's never lost
- Previously, transporter.sendMail() errors were silently eaten by
  callers' .catch(() => {}) in routes/auth.js and routes/agents.js,
  so a revoked/invalid Gmail App Password failed with zero trace -
  signup still returned success with no email ever sent
- No behavior change for callers (still fire-and-forget) - this only
  adds visibility into Render logs for verification/reset/agent
  welcome emails
