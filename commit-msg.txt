Implements the 3 remaining "Not built" items from the feature checklist
(sidebar collapse/expand and hover auto-hide were already working, no
changes needed there).

Centered page header (logo + title), all shell pages:

  needed on 6 of 7 pages
- shell.css: new .page-header styles
- print.html: hand-added header (its title+status layout didn't fit the
  generic approach), hidden in @media print

PWA install ("Add to Home Screen") for the admin app:

  separate from the existing per-site tenant-branded portal PWA)
- shell.js: registers the service worker, injects manifest/meta tags,
  shows an "Install app" button on beforeinstallprompt (Chromium only -
  no programmatic prompt exists on Safari/iOS)

Manual MAC/IP client authorization (no voucher):
- schema.sql: new manual_client_authorizations table, kept separate from
  vouchers so grants never appear in print runs/settlement/commissions
- mikrotik.js: listHotspotHosts(); authorize/revoke reuse existing
  createHotspotUser/removeHotspotUser
- unifi.js: unauthorizeClient(), setClientBlocked()
- omada.js: authorizeClientManual() - UNVERIFIED, sourced from a single
  unofficial forum report rather than TP-Link's own docs; needs a real
  smoke test before relying on it in production. No revoke/block-by-MAC
  endpoint could be confirmed for Omada, left unimplemented on purpose
  (returns 501 rather than a silent no-op)
- sites.js: new routes - GET /:id/clients, GET /:id/manual-authorizations,
  POST /:id/authorize-client, POST /:id/revoke-client. Meraki rejected
  with 400 on all of these (structurally can't support this pattern)
- admin.html: new "Manual access" tab - site picker, live device list
  (falls back to manual MAC entry), duration, optional note, active
  grants table with per-row revoke
