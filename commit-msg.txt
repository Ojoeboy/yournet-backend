fix(pwa): stop service worker from pinning stale shell.js/shell.css forever

- sw.js: switch shell-file caching from pure cache-first to
  stale-while-revalidate. Previously, the browser's SW-update check only
  re-triggers install() when sw.js's own bytes change - editing
  shell.js/shell.css alone (e.g. adding the bottom nav) was invisible to
  any already-installed client indefinitely, since the cached copy was
  served forever with no revalidation. Now the cached copy is still
  served instantly, but a background fetch (kept alive via
  event.waitUntil) always refreshes the cache too, so a stale shell
  self-heals within one extra reload instead of staying wrong forever.

- Bump CACHE_NAME v4 -> v5 so clients already stuck on the old
  cache-first entries get a clean cutover on next activate.

No server-side or route changes; public/sw.js only.
